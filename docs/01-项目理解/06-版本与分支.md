### ★ 版本号和时间顺序是错开的

`v0.1`（2025-02）**晚于** `v1.0.2`（2022-12）三年，但号更小。
作者在 `v0.1` 的发行说明里写得很直白：

> *"Now with a half-baked GUI! … I'm getting lazy and life is kinda getting in the way again
> so I figured I'd just merge the work into main and upload binaries for it.
> It basically mostly works. … Sorry I haven't done more, my bad"*

他把 `jank-gui` 分支合进 `main` 后随手打了个 `v0.1`。所以：

| 你想要 | 选哪个 | 理由 |
|---|---|---|
| 命令行 | **`dist/v1.0.2/acet.exe`** | 最新最全的 CLI（含 LR），且**无任何 DLL 依赖** |
| 图形界面 | **`dist/v0.1/acet-gui.exe`** | 唯一的 GUI 发行版 |
| 命令行（但坚持用 v0.1 那个包里的） | `dist/v0.1/acet-cli.exe` | 行为与 v1.0.2 相同，但**依赖 MSVC 运行库**，见 §三 |

### 各版本随包 README 的差异（考古价值）

发行包里的 `README.md` **不等于**仓库 `main` 的 README，各版本内容不同，
本目录把五个版本的原版 README 都留在了各自的 `dist/<版本>/README.md`。差异摘要：

* `v0.0` 的 README 最有史料价值 —— 它完整写了作者**为什么造这个轮子**：
  试过 Armoured Core 2 Emblem Tool（只吃 SharkPort/X-Port 老格式）和
  Chase 的 vg-resource AC3 工具（导出的图是花的），最后**参考后者的源码**自己逆出格式。
  还提到用 `PS2 Save Builder` 从各种存档格式里抽裸文件。
* `v1.0.0` 起改口：不再说"只支持裸数据"，改成"只要包装没动过裸数据就能用"（.psu / .sps / .xpo）。
* `v1.0.2` 加入 LR 说明：**"Last Raven saves must be passed in as the raw emblem data file directly"**
  —— LR 存在 `BASLUS-21338EMB` 目录里，每个徽章是 `data0` … `data7`。
* 各版本 README 的"已测试作品"清单在增长：v0.0 = AC2/AC2AA/AC3；
  v1.0.0 = 加上 SL(US)/AC3:SL(JP)；v1.0.2 = 再加上 NX/NB/LR。

## 三、二进制分析（本机实测）

用 PE 头解析导入表得到的结果：

| 文件 | 大小 | 子系统 | 编译器 | DLL 依赖 | 能直接跑吗 |
|---|---|---|---|---|---|
| `v0.0/acet.exe` | 2,947,664 | 控制台 | MinGW GCC 9.2 | `KERNEL32`, `msvcrt` | ✅ 自带全部依赖 |
| `v1.0.0/acet.exe` | 2,945,187 | 控制台 | MinGW GCC 9.2/9.3 | `KERNEL32`, `msvcrt` | ✅ |
| `v1.0.1/acet.exe` | 2,948,626 | 控制台 | MinGW GCC 9.2/9.3 | `KERNEL32`, `msvcrt` | ✅ |
| **`v1.0.2/acet.exe`** | 2,949,247 | 控制台 | MinGW GCC 9.2/9.3 | `KERNEL32`, `msvcrt` | ✅ |
| `v0.1/acet-cli.exe` | **128,000** | 控制台 | **MSVC** | `MSVCP140`, `VCRUNTIME140`, `VCRUNTIME140_1`, `api-ms-win-crt-*` | ⚠ **需要 VC++ 运行库** |
| `v0.1/acet-gui.exe` | 5,327,872 | 窗口 | **MSVC** | 同上 + `COMCTL32`/`USER32`/`GDI32`/`ole32`/… | ⚠ **需要 VC++ 运行库** |

### ⚠ `v0.1` 的两个 exe 不自带运行库

`v0.1/acet-cli.exe` 只有 **128 KB** —— 因为它是 **MSVC 动态链接**的，不是静态构建。
它依赖 `MSVCP140.dll` / `VCRUNTIME140.dll` / `VCRUNTIME140_1.dll`
（即 **Visual C++ 2015–2022 可再发行组件包 x64**），而**发布包里没带这几个 DLL**。

* 本机 `C:\Windows\System32` 里三个 DLL 都在 → 能跑（本目录的交叉验证就是用它跑的，当时 25/25 全过）。
* 干净系统上如果没装过 VC++ 运行库，**双击会直接报"缺少 MSVCP140.dll"**。
  解法：装 [Microsoft Visual C++ Redistributable x64](https://aka.ms/vs/17/release/vc_redist.x64.exe)，
  或者干脆改用 `v1.0.2/acet.exe`（MinGW 静态构建，什么都不用装）。

### 版本间的体积差异说明了什么

`v1.0.0` → `v1.0.2` 的 exe 只涨了约 4 KB（2,945,187 → 2,949,247），
而功能上加了 LR/NX/NB 支持。也就是说 LR 支持是**纯逻辑改动**（多一个偏移常量、
多一个 `isLR` 分支、跳过乱序重排），没有引入新依赖 —— 与源码一致。

GUI 的 5.3 MB 主要来自**静态链接的 wxWidgets**。CLI 的 2.9 MB 来自
MinGW 静态链接的 libstdc++ 与 LodePNG。

## 四、构建（如果你想自己编译）

本机（2026-10-04 检查）**没有** `cmake` / `cl` / `g++` / `ninja` / `make` 在 PATH 上，
所以本目录没有自行编译产物，`dist/` 里全是官方原版二进制。

上游 README 给的最短路径：

```
mkdir build
cmake -S . -B build/
cmake --build build
```

`CMakeLists.txt` 的要点：

* 顶层需要 **CMake ≥ 3.14**，C++ 标准 **17**，产物统一输出到 `${CMAKE_BINARY_DIR}/bin`。
* `add_subdirectory(acet / acet-gui / acet-cli)` —— **`acet-gui` 是三者的中间一个**，
  所以**即使你只想要 CLI，配置阶段也会去拉 wxWidgets**。
  作者自己吐槽过："I'm pretty bad with cmake and I know there is some shit I still need to sort out"。
* `acet-gui/CMakeLists.txt` 用 `FetchContent` 从 GitHub **浅克隆 wxWidgets 源码**从头编译；
  如果系统里装了 wxWidgets 就 `FIND_PACKAGE_ARGS` 找到它。**只编译 CLI 的话建议临时
  把 `add_subdirectory(acet-gui)` 注释掉**，否则要等很久。
* `acet-cli` 显式要求静态链接：`-static`、`CMAKE_FIND_LIBRARY_SUFFIXES ".a"`、`BUILD_SHARED_LIBS OFF`
  —— 这就是官方 `acet.exe` 无依赖的原因。

### 想要 `dev` 分支的 PS1 功能

```
git -C src/ac-emblem-tool worktree add ../acet-dev origin/dev
cd ../acet-dev && mkdir build && cmake -S . -B build/ && cmake --build build
```
（`PS1Dialog.h` 是 `dev` 才有的头文件，`main` 上不存在。）

## 五、本目录保留了什么

```
src/ac-emblem-tool/     完整 git 仓库（20 提交 / 3 分支 / 5 tag），未做任何改动
dist/v0.0/              发布包 zip + 解包后的 acet.exe + 随包 README
dist/v1.0.0/            同上
dist/v1.0.1/            同上
dist/v1.0.2/            同上
dist/v0.1/              acet-gui.exe + acet-cli.exe + LICENSE + README
```

**每个版本都同时保留"原始 zip"和"解包后的文件"**：zip 是存档用的原始面貌
（校验和以它为准），解包出来的是能直接双击/命令行调用的形态。
所有文件的 SHA256 见 `docs/03-来源与校验和.md`。
