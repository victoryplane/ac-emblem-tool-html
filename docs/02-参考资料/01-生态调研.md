### ★ 2000 年代日本侧的"记忆卡读写器"路线（历史背景）

那个年代日本玩家的通行做法不是模拟器，而是**买一个第三方 PS2 记忆卡读写器**，
把存档导成 `.psu` 之类的格式再在 PC 上改：

* **GAMETECH「メモリージャグラー」（Memory Juggler）** —— ★ 有实证：kappa 的
  MutuallyLastRaven 说明里明确写着它是为 Memory Juggler 形式的 LR 徽章数据写的
  （PSU ⇄ BMP，见 §二 的 MLR 行，原文引自 RR 论坛 tid=2661）；
* **EMS 的 PS2 记忆卡读写器** —— `.psu` 格式就是以它命名的
  （那份 `.psu` 文档标题就是 *"for EMS Adapter"*）；
* 同期还有 SharkPort / X-Port（`.xpo`/`.spo`）、Action Replay MAX（`.max`）。

⇒ **这解释了为什么生态里一半的工具只吃 PSU**：那是当年唯一的现实通路。
⇒ 对做记忆卡支持的启示：**`.psu` 不是一个随便的中间格式，而是这一整片工具链的公共语言**，
值得优先支持（见 `../01-项目理解/04-记忆卡与存档处理.md` §十 的性价比排序）。

⚠ **一处未能证实**：有线索称日本「Armored Core ACPedia」（`armoredcorefan.com`）
记载过"PS1/PS2 时代可用 Memory Card Juggler ＋ 编码器导入 PC 画的图"，
但该站点 `[死链/不可达]`（`http://` 与 `https://` 都取不到），**这条引用无法复原**。
不过其**内容**与 MLR 说明书的表述一致 ⇒ 这条工作流本身是可信的。

## 六、值得记住的几个"跨工具共性"

1. **透明度永远是 1 bit**。acet 用 `0x80` 表示不透明；PSX-Emblem 用 `A < 0x80`；
   PSP savedata 用 `A == 0` 表示透明；MLR/zk306 用"指定一个调色板索引当透明色"。
   **没有一种工具支持半透明** —— 这是这些世代硬件的共同约束。
2. **颜色上限都在 255/256 附近，且"超限就丢弃"是通行做法。**
   zk306 的说明原文：*"colors beyond the first 256 will be dropped,
   pixels using these colors will be rendered transparent."*
   —— 与 acet 那个差一 bug 的**失败方式完全一样**（第 257 项索引截断成 0 = 透明）。
3. **图像输入规格五花八门**是最大的互操作陷阱（完整对照表见
   `../01-项目理解/03-图片处理管线.md` §七）。
4. **左右镜像**反复出现：zk306 要求输入预先水平翻转、MLR 1.01 修过镜像 bug。
   acet **不做任何翻转**（真实存档提取出来的红玫瑰是正立的）。
   `[未观测]` 写回去后游戏内是否镜像 —— 值得实机确认一次。
5. **这些工具的作者都只有一台主机、一两个游戏**（zk306 原话：
   *"i won't make a converter for other versions of AC (largely because i only have AC:LR for ps2 XD)"*）——
   所以 acet 能覆盖 AC2→LR 全世代其实是件不容易的事。
