# PS2《装甲核心》徽章工具 · 网页版

**单个 HTML 文件、双击离线打开、别人 0 安装。** 把 PC 上任意一张图变成 PS2《装甲核心》
能用的徽章，直接写进记忆卡；也能反过来看 / 导出 / 搬运卡上的徽章。

---

## 一、怎么构建（只有一步）

```powershell
cd <你 clone 下来的 emblem-tool 目录>
node web\build.mjs
```

产物固定在 **`web\dist\emblem-tool.html`**（约 440 KiB）。**双击它就能用**，不需要服务器、
不需要联网、不需要装任何东西。

| 命令 | 作用 |
|---|---|
| `node web\build.mjs` | 打包 + 自检（自检失败**非零退出**） |
| `node web\build.mjs --check` | 只对**已有**产物做自检，不重新打包 |
| `node web\build.mjs --verbose` | 顺带打印模块图（每个模块的依赖数 / 导出数） |

要求：**Node ≥ 22.13（本机 24.14.1）**。构建器用 `node:module` 的 `stripTypeScriptTypes()`
做类型擦除 —— **没有 npm 依赖、没有 `package.json`、没有 `node_modules`、不联网。**

构建时会做的自检（任一不过就非零退出）：

1. `dist\` 里只有 1 个 html，文件名是 `emblem-tool.html`；
2. 恰好 1 个 `<script>`、**没有** `type="module"`；
3. 脚本里（抹掉注释/字符串之后）**没有** `import` / `export`，也没有误嵌套的 `</script`；
4. 全文**没有** `http://` / `https://` / `src="./` / `href="./` / `<link>` / `<img>` / `fetch(` 之类外部引用；
5. 每个模块变换后的代码**能被 JS 引擎解析**，且模块里没有残留的真代码 `require(`；
6. **引导冒烟**：在 `node:vm` 里用最小 DOM 桩把整包跑一遍（证明没有残留 TS 语法、
   模块初始化不会炸、`main.ts` 引导代码跑到底）；
7. **取景冒烟**（v0.6 起，v0.7 加强）：在同一个桩 DOM 里塞一张 **1024×600** 的源图，
   真的走一遍「进取景视图 → **拖动 30 次 + 滚轮 10 次** → 〔确定取景〕→ 再进 → 〔取消〕」，断言：
   * ★ **窗口 → 参数**的契约：倍率 = `128 / 窗口边长`、`X/Y` = 窗口左上角（源像素口径），
     **且 128×128 里至少有内容** —— 旧代码在这一步烘出 **0 个不透明像素**，也就是用户报的
     「按了确定取景以后图片消失」；
   * ★ **性能契约**：那 40 次取景动作里 `prepareEmblem()` 调用 **0** 次、面板刷新 **0** 次、
     新建 canvas **0** 个；〔确定取景〕之后 ⇒ **各 1 次**；〔取消〕⇒ **0 次**（见 §六 的性能那条）；
8. 打印体积与行数。

## 二、怎么用

1. **先完全退出 PCSX2**（它退出时会用手里的旧卡写回文件，你的改动会被覆盖）。
2. 双击 `web\dist\emblem-tool.html`。
3. 顶栏 **「选择记忆卡（可覆盖保存）」** → 选 `memcards\*.ps2`
   （Chrome 下能拿到写句柄 ⇒ 保存时直接覆盖原卡；其它浏览器会退化成"下载"）。
   * 也可以直接把 `.ps2` **拖到顶栏「记忆卡」那一块**上（Chrome 下拖放同样能拿到写句柄）。
   * 那个〔拖入 / 只读选择〕按钮在 **v0.10 已按用户要求删除**（"没用"）：只读兜底仍在，
     但改成**自动**的 —— `showOpenFilePicker` 不可用/被拒时工具自己走隐藏文件框。
4. 把图片**拖进左上的图片格**，或点「选择 / 粘贴图片」，或直接 **Ctrl+V** 粘贴。
5. ★ **导入后会自动进入取景模式**（v0.16，用户要求）—— 不用再点〔取景…〕：
   **拖动图片**把要的部分放进**白色方框**里（滚轮缩放：往里滚 = 放大、往外滚 = 缩小到能看见整张图），
   白框下面那行是**实时读数**，满意就按 **〔确定取景〕**（想放弃按〔取消〕）。
   * 想手动再进取景模式：点那一格上方的 **〔取景…〕**（进/出同一个按钮）。
   * ★ **打开图片时默认已经"填满白框"**（v0.9，用户要求）：白框里是满的、没有透明边，
     打开就能直接用；想换个位置就拖、想缩放就滚轮。
   * ★ 拖动时**只有白框里的画面在动**：参数行与「当前图片」**等〔确定取景〕才更新一次**
     （用户要求："确定取景以后再更新面板"）。这是**故意**的 —— 见 §六 的性能那条。
6. 选作品（LR / SL / NX 有实机证据，其余标「未验证」），点下面要写的槽，
   点 **「写入选中槽」**。
7. 工具会：生成徽章块 → 在**内存副本**上写 → **回读**逐字节比对 + 18 段校验 + ECC
   自检 → 全过才弹确认框 → 覆盖原文件（或下载）。

> ⚠ 「卡上没有这个作品的目录」时会被**拒绝**：非 LR 的每个槽是一个完整存档目录
> （除徽章还有 `icon.sys` 与图标文件），只建目录会写出游戏不认的半成品。
> 解决办法：先在游戏里往那个槽存一次徽章。

* ★ **上区 = 一格"当前图片" + 右侧参数侧栏**（`.upper` = `minmax(0, 1fr) minmax(190px, 220px)`，0.23 收窄）。
  0.22 用户定：**不做内置像素编辑器**（原右栏那个「工具侧栏」整块删掉），右栏改放**参数** —— 依据、
  替代流程与"闭环无损"的判据见 `SPEC.md` §六。
  「原图」面板已经删掉 —— 但选图 / 拖入 / **Ctrl+V 粘贴** 的功能一个都没少，搬到了那一格上方的**细工具条**里。
  断点：宽屏左右两列 → **≤1100px 上下堆叠**（图片格在上、参数在下）。
  ⚠ 旧的 ≤760px / ≤900px 两条规则已删（它们只为工具侧栏与"横向参数行"存在，两者都没了）。
* ★ **图片那一块大面板是"方角矩形"**（0.7 那一版，用户追加）：`.pane-image` / `.stage` / `.image-toolbar` /
  取景图层都是 `border-radius: 0` + 1px 细边框 + 深色底铺满 —— 一块画布面板，而不是圆角卡片。
  **只有这一块**改了；参数侧栏 / 8 槽 / 自检区仍是原来的圆角卡片。
  白框（`.crop-frame`）的形状**不受影响**：它本来就是正方形，尺寸由舞台决定。
* ★ **工作区（那块黑色区域）自动填满左格**（0.9 那一版，用户："我截图中红圈部分，能不能改成自动填满
  或者说适应这一个长方形区域"）：`.stage` = `flex: 1 1 auto` + `width: 100%` +
  `min-height: clamp(320px, 62vh, 760px)`（**兜底是必需的**：里面两层都是绝对定位，窄屏堆叠时没有它会塌成 0；
  宽屏时它是"这块工作区至少多高"的旋钮 —— **62vh 是量出来的**：4× 预览要 512px、加内边距要 ≥524px 的舞台，
  852px 高的视口上 62vh = 528px 正好装得下；`56vh` 只有 477px ⇒ 预览被压成 465px，见 §v0.10），
  **没有** `aspect-ratio`、**没有** `max-width` ⇒ 形状随窗口变化（长方形），不再固定边长。
  * 上一版（0.8）是"正方形 + 上限 560px + 居中"，用户看过截图后改口要"填满"；
  * **白框规则一个字没动**（仍是固定正方形、工作区**短边** × 70%、夹在 `[120, 420]`）——
    工作区变大，白框跟着变大（例如 700×430 ⇒ 301px）；
  * **没有**改 `.upper` 的列定义（2fr / 1fr）：这轮说的是"填满左格"，不是"加宽左列"。
    备选方案（"宁可挤压右侧工具" ⇒ `minmax(0,2.4fr) minmax(240px,1fr)`）以**注释**形式写在 `.upper` 那里，
    用户没定、别默认启用。
* ★ **取景是"按需"的**（不再常驻显示原图）：点那一格上方的〔取景…〕，**在同一格里**切成取景视图。
  0.6 起交互只有一个动体（用户 2026-10-05 定的），0.7 起拖动**只动视觉**：
  * 屏幕正中是一个**固定不动的白色方框**（"取景示意区"，位置/边长只看舞台大小，由
    `logic/cropGeometry.ts::frameRectFor()` 算出来）；
  * **拖动图片**（在哪儿拖都一样）= 平移源图，把要用的部分**拖进白框**；
  * **滚轮** = 以**白框中心**为锚点缩放；往里滚到"白框 = **128 源像素**"就**停**（0.11 起
    **不允许把源图放大** —— 再小就是把几个像素吹成 128×128，出来是一堆麻点，用户附截图报的就是这个）；
  * ★ **白框正下方那行就是实时读数**（0.12 起）：`白框 512×512 源像素 · 左上角 (x, y) · 倍率 0.250`，
    到极限时接 `· ★ 已到最小（1:1，不能再放大）` 并变**警示色**。
    ⚠ 这些数字**也**写进页面最下面的状态行，但那条在 8 槽那一块 —— 取景时看不到，所以上面这行才是
    你该看的地方（用户原话："ok了，然后状态行在哪"）；
  * ★ **打开图片时的默认取景 = "填满白框"**（0.9，用户："图片默认就顶住这个方框部分，图片的一边顶住就行，
    顶住就停，不缩放"）：窗口边长 = 源图**短边**、居中 ⇒ 白框里全是图、没有透明边。
    〔**确定取景**〕= 烘焙框内内容为 128×128；〔**取消**〕= 回滚到进入取景前的参数；
  * ⚠ **〔↺ 复位 / 适应〕与细工具条上的〔↺ 恢复到适应〕都已按用户要求删除**（0.9，他的原话是
    "我认为这个按钮没用，删了吧"）。它是上一版那个"整张图缩进框里"默认值的配套按钮，
    点下去只会把图缩回"整张图"，与他要的相反。想回到默认取景 = 重新导入图片，或直接改「取景数值」；
  * ★ **拖动/滚轮期间只改源图的 `transform`**：不跑管线、不重建任何面板、不改参数
    （`requestAnimationFrame` 合帧，一帧最多写一次样式）—— 参数行与「当前图片」
    等〔确定取景〕那一下**一次**更新；〔取消〕连管线都不跑。**这是用户要求的行为，不是偷懒**（见 §六）；
  * 想收起取景视图也可以再点一次工具条上的〔取景…〕：**还有没确定的调整就等同〔确定取景〕**
    （照常写参数、跑自检），没有调整就直接收起 —— 不会静默丢掉刚拖好的取景；
    想**放弃**调整请按〔取消〕；
  * ★ **所见即所得是构造性的**：白框框住的那块源图**就是**被裁下来的那块 ——
    屏幕侧（`imagePlacement`/`screenToSource`）与参数侧（`windowToManual` → `prepareEmblem`）
    由 `ui.test.ts` 分节 (l) **逐点比对**（拿真实核心算，不是"看代码觉得对"）；
  * 〔确定取景〕前会跑**烘焙自检**：源图那块有内容、输出却是空的（或还有半透明像素、尺寸不对）
    就**报错并且不关视图**，绝不静默给你一张空白；
  * 取景时右下那句"已按容器缩放显示"会**藏起来**（它讲的是旁边那块预览）；
  * 取景视图**也不出现滚动条**（`overflow: hidden`）；
  * 参数行里的「**取景数值**（倍率 / X / Y）」在 **0.15 已按用户要求删掉**（连"收边 / 减色上限"一起）。
    现在要看当前取景的几个数，只有**取景视图里**那行实时读数（白框下面）—— 这也够用：
    需要精确值的地方都是**边界**（X/Y 顶到 0 或最大值），而拖到边界会被自动夹住 = 精确值。
* ★ **右栏是参数**（0.22 起）：两格 —— 缩放核（下拉）与 alpha 阈值（滑杆 + 数字框）。
  ⚠ 它原来在 `</main>` 之后**独立一整行**；0.22 用户定"把参数一栏放在右栏"，因为原来那栏的
  「工具侧栏」（像素编辑器占位）**整块删掉了** —— 内置编辑器不做，理由与替代流程见 `SPEC.md` §六。
* 三块内容区（图片格 / 8 槽 / 自检）**都不出现滚动条**：容器 `overflow: hidden`，
  画布等比自适应（`aspect-ratio: 1/1` + `max-width/max-height: 100%` + `image-rendering: pixelated`）。
  ⚠ 取景视图里的**源图**是例外：它按**自然尺寸**做 CSS 像素、再整体 `transform: translate/scale`
  （因此**不能**给它 `max-width: 100%`，否则浏览器会二次缩放，指针换算就跟屏幕对不上了）。
* 「预览倍率」的语义是**期望上限**：装不下就自动缩到刚好装下，并在那一格下方淡淡标一句
  `已按容器缩放显示：期望 8×（1024px）→ 实际约 N×（…px）`。
* **游戏预览按「索引 0」渲染**（实机验证过的口径）——不这么做，你看到的和游戏里不一样。
* ★ **下面的 8 个槽 = 当前所选作品的 8 个槽**：切作品会**换一整套槽**。
  过滤按**盘序列号**匹配（区域前缀 `BA`/`BI` 不参与比较）：
  LR 日版 ⇒ 只显示 `BISLPS-25462EMB` 的 `data0..7`；NX ⇒ 只显示 `BISLPS-25338E##`；
  SL ⇒ 只显示 `BISLPS-25169E##`；自定义序列号 ⇒ 匹配该序列号的目录。
  被过滤掉的目录写在 8 槽摘要行的"**卡上还有其它作品：…**"里（**不许静默隐藏**），例如：

  ```
  占用 4 / 8　空 4　（本作品目录：BISLPS-25462EMB）　卡上还有其它作品：BISLPS-25338E00…E04、BISLPS-25169E00…E01（切作品查看）
  ```

  该作品在卡上还没有目录时，8 个槽全空、空槽提示写"卡上还没有这个目录"，**写入会被拒绝**
  并提示"先在游戏里为这个作品存一个徽章"。
* ⚠ 动参数会**整份重算**：`rgba` 不变但 `palette`/`indices` 的编号顺序会变，
  所以界面**不缓存 indices**（`PORT-NOTES.md` §五 的最后一条）。
* 页脚那两行说明文字已按用户要求删除。**安全提示没丢** ——
  「先完全退出 PCSX2」仍然写在「写入选中槽」的**确认框**里（`ui.test.ts` 有断言钉住）。

### PCSX2 自检怎么用（面板在页面最下面）

它解决的问题：**你在 PCSX2「设置 → 记忆卡插槽」里选的卡，可能不是游戏实际读的那张** ——
PCSX2 还有一层「每游戏设置」（`gamesettings\<序列号>_<CRC>.ini`）会**盖掉**全局设置。

> ★ 浏览器不允许网页**凭路径**读本地文件（`file://` 也一样）。所以"默认找到
> `C:\Users\M\Documents\PCSX2`"做成了 **一次点击 + 记住上次的位置**：

| 方式 | 什么时候用 | 说明 |
|---|---|---|
| **① 选择 PCSX2 目录**（主路径） | 默认 | 用 `showDirectoryPicker({ id: 'pcsx2', startIn: 'documents' })`：第一次直接开在"文档"，`id` 让 Chrome **记住**你选的目录；句柄还会存进 IndexedDB，下次打开若权限还在就**自动读一遍**（不弹权限框）。 |
| **② 用目录输入框选**（兜底） | 浏览器没有 `showDirectoryPicker`，或它抛 `SecurityError` 时**自动**切过来 | `<input type="file" webkitdirectory multiple>`，按 `webkitRelativePath` 匹配三个文件。**不依赖 File System Access API。** |
| **③ 拖进来** | 随你 | 三个文件或整个目录都收（拖目录时走 `FileSystemEntry` 递归）。 |

三条路都会在面板上写明**这次走的是哪条**（"本次来源：目录选择框 / 目录输入框 / 拖入文件 / 自动（记住的目录）"），
读进来**立刻**出结论表，不需要再点一次。**全程只读，不写任何文件。**

### 版本号规则

`src/ui/logic/version.ts::APP_VERSION` 是**唯一**来源（顶栏、欢迎日志、构建日志都用它）：

* 从 **0.1** 起，**每次交付 +0.1**（0.1 → 0.2 → 0.3 …）。变更历史记在 `CHANGELOG.md`（0.19 起从
  `version.ts` 搬出去 —— 打包器不删注释，旧写法等于让产物白背 ~15 KB 历史）。
* **只有用户明确说"可以发布了"，才允许进 1.x 正式版。**
* 打包时 `build.mjs` 会把这个常量替换进顶栏（HTML 里只留 `data-app-version="v?"` 占位符），
  所以 **JS 没跑起来时也不会显示 `v?`**；`ui.test.ts` 会断言产物里的版本号与之相符。
* 另有 `UI_BUILD_TAG`（`M4-UI-28` 这种）—— 那是**给我们看的开发标记**，用来确认
  "用户打开的不是缓存页"，与交付版本无关，每次界面改动 +1。

| 工作区下限抬到 `62vh` | 4× 预览要 512px ⇒ 舞台要 ≥524px。`56vh` 在 852px 高的视口上只有 477px，把预览压成 465px |

`fitDisplaySize()` 量了 `#view-preview` 之后写上去的 ⇒ **量一次缩一次**：
128 → 116 → 104 → … → 实测 **68px**，页面底部还诚实地写着
`已按容器缩放显示：期望 4×（512px）→ 实际约 0.53×（68px）`（用户就是看到这句才来问的）。
教训：**除 JS 量尺寸的容器自己必须有确定尺寸**，别让"被量的东西"和"依赖它的东西"互为输入。
现在 `ui.test.ts` 分节 (j)⑭ 把这两条（CSS 有 `width/height: 100%`、JS 量 `.stage`）都钉住了。

### v0.9：工作区"填满" + 默认取景"填满白框" + 删掉两个复位按钮

用户看了 0.8（正方形工作区）的实机截图后，一口气提了三条 + 两处删除：

| 用户原话 | 这一版怎么做 |
|---|---|
| "我截图中红圈部分，能不能改成**自动填满**或者说适应这一个长方形区域" | `.stage` 去掉 `aspect-ratio` 与 `max-width`，改成 `flex: 1 1 auto` + `width: 100%` + `min-height: clamp(...)`（兜底 + 下限；数值在 v0.10 调成 `62vh`）⇒ 随窗口自动填满左格 |
| "每次打开图片，图片默认就**顶住这个方框**部分，图片的一边顶住就行，顶住就停，不缩放" | 默认取景改成**填满白框**：`cropGeometry.fillWindow()` 的窗口边长 = 源图**短边**、居中（`fillScaleFor()` = `128 / 短边`） |
| "我认为这个按钮没用，删了吧"（〔↺ 恢复到适应〕/〔↺ 复位 / 适应〕） | 两个按钮 + `fitCropToImage()` + `resetManual()` 全部删除；`fitManualToTarget()` 改名 `fillManualToTarget()` |
| "实色 N · 半透明 N 这部分也删了，没用" / "→ 目录名 …这部分也删了" | 细工具条的 `#original-badge` 只留「文件名 · 尺寸」；`renderGameNote()` 不再输出「→ 目录名 …」 |

**为什么"越点越小"（用户上一轮的疑问，根因）**：老口径下 `窗口边长 = 源图长边`（= 整张图缩进框里、
短边方向留透明边）。所以"恢复到适应"按一下就把画面缩回"整张图"那个小尺寸；
而用户想要的恰恰是**填满**。图标尺反过来（短边贴框）之后，默认画面就是满的，那个按钮自然没用了。

**`min-height` 那条兜底不能省**：窄屏（≤1100px）时上下堆叠，这一格的高度不再由同排的参数侧栏决定，
而舞台里那两层（`#stage-final` / `#stage-crop`）都是 `position: absolute`（没有内在高度）⇒
没有 `min-height` 会直接塌成 0。`ui.test.ts` 分节 (j)⑬ 有断言。

**顺手修掉的另一个 bug（`[hidden]` 被 `.row` 盖掉）**：这一轮我用无头 Chrome 给产物截图核对版式，
发现**没进取景视图时**，那一行 `拖动图片，把要用的部分放进白框里（滚轮缩放）〔确定取景〕〔取消〕`
竟然也在页面上 —— 原因是浏览器默认的 `[hidden] { display: none }` **优先级低于作者写的
`.row { display: flex }`**，`hidden` 属性形同虚设。修法是在 `styles.css` 顶部加一条
`[hidden] { display: none !important; }`（`ui.test.ts` 有断言钉住）。
★ 教训：**`hidden` 属性不能当成"一定不显示"**，凡是有 class 会设 `display` 的元素都要显式写 `[hidden]` 规则。

### v0.8：工作区正方形（为什么当时必须有上限）

用户看了实机截图后说：「我是指红圈里的一整块，能不能做成**方形的**，可以**挤压右侧的工具**」。
（⚠ 这条在 0.9 被用户自己推翻了 —— 现在是"填满"；下面这段留着是为了解释当时为什么必须有上限。）

`.stage`（那块黑色工作区）加三条：

| 规则 | 作用 |
|---|---|
| `aspect-ratio: 1 / 1` | 高由宽推出来 ⇒ **永远是正方形** |
| `max-width: 560px` | ★ **最大边长上限**：没有它，1920px 窗口下左列 ~1200px 宽 ⇒ 正方形会变成 1200×1200，整页长得没法看 |
| `margin-inline: auto` | 超宽屏下这块方的工作区在面板里居中（左右留白对称） |

配套：把 `flex: 1 1 auto` 改成 `0 0 auto`、并**去掉原来的 `min-height: 300px`** ——
纵向 flex 的 `flex-grow` 会跟 `aspect-ratio` 抢高度；而 `min-height: 300px` 在窄窗口（宽 < 300）下
会把高度顶到 300，两种都会让它**不方**。这两点都写成断言钉住了。

**上限为什么取 560**：白框 = 工作区短边 × 70%、上限 420 ⇒ 560 给出 **392px** 的白框，
四周各留 **84px** 给"框外压暗"（这就是用户说"框看起来更满"的来源）；工作区再大（≥ 600）
白框就顶到 420 的上限，多出来的宽度对取景没有帮助，只是把页面撑长。
窄窗口下 `width: 100%` 让它自然缩小，`aspect-ratio` 保证仍是正方形。

**那"挤压右侧的工具"呢？** 故意**没改** `.upper` 的列定义：工作区边长由**上限**决定，
把左列从 2fr 放宽到 2.2fr 并不能让它变大，只会让面板里多出更多留白（右侧工具栏被挤窄了却什么也没换来）。
两个一起改才有意义（`max-width` 抬到 ~700px + 左列放宽），那属于"工作区要更大"的备选 ——
已按注释形式写在 `.upper` 那里，另附"整个左面板要接近正方"的备选写法，**用户没定，别默认启用**。

**取景结果有没有变？没有。** 取景窗口（源像素）与烘焙结果只跟源图尺寸和窗口有关，
工作区变方只改变**显示倍率 k** 与**白框的像素边长**（364 → 392）⇒ 打包冒烟里的
"倍率 0.125 / 偏移 (0,−212) / 不透明 9600/16384"**一个都没变**（桩环境里舞台盒子本来就是 0×0，另说）。

### v0.7：取景拖动为什么曾经卡（实测数字）

用户反馈：「取景时拖动/滚轮**有点卡**」，并给了处置意见「如果是面板不断刷新导致的，
那就改成**确定取景以后再更新面板**」。查下来他的猜测是对的，而且比预想的严重得多 ——
**旧代码每挪一个像素就把整条管线重跑一遍**：

| 一次 `pointermove` 旧代码跑的东西 | 照片类源图（1000×800，~80 万色） | logo 类源图（1000×800，64 色） |
|---|---|---|
| `prepareEmblem()`（缩放 + alpha 二值化 + **中位切分量化**） | **298 ms** | **53 ms** |
| `imageStats()`（统计面板里把**整张源图**扫一遍 + Set 去重） | **99 ms** | 10 ms |
| 合计（60fps 的预算是 16.7 ms/帧） | **≈397 ms** | ≈63 ms |

也就是说：一次拖动是整帧预算的 **4~24 倍**，而且 `renderStats()` 还在每次移动时
`clear()` + 重建十来行 DOM。拖动真正需要的几何运算（`panWindow` + `imagePlacement`）
实测只有 **0.001 ms**。

修法（按用户意见）与**可观测判据**：

* 取景期间 `applyDrag()` / `applyZoom()` **只改源图的 `transform`**，
  用 `requestAnimationFrame` 合帧（一帧最多写一次样式）、`setPointerCapture` 拖拽、
  滚轮 `{ passive: false }` + `preventDefault()`（顺带解决"滚轮带着页面滚"）；
* 舞台尺寸走**缓存**，拖动过程里**一次 `getBoundingClientRect()` 都不读**（避免 layout thrash）；
* 参数与面板一律等〔**确定取景**〕提交一次：`commitWindow()` → `recompute()` + `refreshImage()`；
  〔**取消**〕连管线都不用跑（参数从头到尾没被改过）；
  **再点一次工具条上的〔取景…〕收起**时：有未提交的调整 ⇒ 等同〔确定取景〕；没有 ⇒ 直接收起；
* 离开取景视图时的"重新量尺寸"走**轻量**回调 `onRelayout`（只重画 128×128 预览画布，
  不重算、不重建统计面板；顺手也把「预览倍率」下拉改成只重画预览）。
* ★ 判据（不是"应该快了"）：`ui.test.ts` 分节 (l9) 做源码级断言，打包器**取景冒烟**做运行时断言 ——
  桩 DOM 里 30 次拖动 + 10 次滚轮 ⇒ `prepareEmblem()` **0** 次、`refreshImage()` **0** 次、
  新建 canvas **0** 个；〔确定取景〕⇒ **1/1** 次；〔取消〕⇒ **0** 次。
  在浏览器 F12 里也能自己读：`EmblemToolCore.ui.pipeline.pipelineStats()`。

### v0.6 修掉的两个 bug（都记在这里，免得再犯）

用户的原话是：「为什么按了确定取景以后图片会消失」。根因有**两个**：

1. **取景偏移的量纲错位**（`logic/defaults.ts::toPrepareOptions`，真凶）。
   界面的 `manualOffsetX/Y` 口径是**源像素**（"目标图左上角对应源图的哪一点"），
   而 `core/image.ts` 的 `offsetX/offsetY` 是**目标像素**（`tx = sx·scale + offset`）。
   旧代码原样传过去 ⇒ 对**非正方形**图就是一次巨大的错误位移：
   1000×800 只剩 384/16384 个不透明像素（一条缝），**1024×600 直接 0/16384（全空）**；
   正方形图两套口径恰好都是 0，所以"有时候是好的"。
   取景视图里画的是**源图本身**（永远看得见），一〔确定取景〕就切回 128×128 的预览 ——
   而那份预览是空的 ⇒ 用户看到的就是"图片消失"。
   现在换算只在 `manualOffsetToTarget()` 里做**一遍**（取反 ×scale），并有逐条回归断言。
2. **取景框的几何算错**（`cropView.ts` 旧版）：符号反了 + 多乘/少乘一个 `scale`，
   框又小又偏（1000×800 那张实测 6.6px vs 应有的 400px）⇒ **框里看到的不是被裁下来的那块**。
   v0.6 换成"**以白框框住的源图区间为唯一原始状态**、参数是派生结果"的模型，
   所见即所得变成**构造性**的，不再依赖任何一次换算是否正确。

顺带修的：拖到极限时可以把图整张拖出白框（输出全透明 ⇒ 也像"图没了"）——
现在 `clampWindow()` 保证白框里永远有图，且〔确定取景〕有烘焙自检兜底。

## 六、出了问题怎么自查

**第一步永远是开 F12 看 Console。**

1. **F12 → Console**（控制台），有没有**红色报错**？
   * 红色 = JS 抛异常（不是"提示"）。把红字整段截图发我 —— 尤其是第一行
     `Uncaught ... at ...`，它带**行号**，能直接定位到产物里的位置。
   * 本工具装了全局兜底：未捕获的异常/未处理的 Promise 失败都会弹一条红色提示条，
     所以"点了没反应"这种情况本身就是一个 bug，请连同 Console 的红字一起报。
2. **确认你打开的不是缓存页**：看**顶栏**那个版本号（`v0.26`）—— 0.18 起写入日志不再有"欢迎…"那行
   （界面上不放说明性长句），开发标记改在 F12：`EmblemToolCore.ui.buildTag`。
   * 版本号来自 `version.ts`；`M4-UI-N` 是界面开发标记，每次界面改动都会 +1。
   * 如果和你拿到的新产物对不上 ⇒ 你开的是旧文件（关掉标签页重新双击
     `web\dist\emblem-tool.html`，别用浏览器历史/书签打开）。
3. **提示"这张卡在磁盘上又被改过了 ⇒ 拒绝写入/操作"**（`v0.25` 新增的写前拦截）：
   意思是**磁盘上这张卡在工具读过之后被别的进程写了一次** —— 最常见就是 **PCSX2**（游戏里存了徽章，
   或者它退出时把手里的卡写回文件）。Chrome 会拒绝往过期句柄上写（`InvalidStateError`），所以工具
   干脆在动手前就拦住，**磁盘一个字节都没动**。照它给的三步做：
   ① 完全退出 PCSX2；② 顶栏〔选择记忆卡〕**重新选一次**这张卡；③ 再操作一次。
   ⚠ 别用〔另存为…〕存出来的副本盖回那张卡 —— 内存副本是基于**旧的**读，会抹掉 PCSX2 期间写进去的改动。
4. **"写入被拒绝"时先看右下日志的红字**（`❌ 槽位 N：…`）。常见三种：
   * `卡上没有目录 …E##` ⇒ 这个作品在卡上还没存过徽章，先在游戏里存一个；
   * `18 段校验不通过` / `ECC 坏页` ⇒ **没写盘**，卡还是原样，把这行发我；
   * `图像不合规` ⇒ **看那行红字里的原因**（v0.17 起界面上不再常驻合规面板了）；
     想知道管线的细节：F12 → `EmblemToolCore.ui.state.prepared.report`。
4. **想手查内部状态**：Console 里可以直接用
   * `EmblemToolCore.ui`（当前界面状态与版本）、
   * `EmblemToolCore.ui.cropView`（取景视图：`setCropView(true)` / `applyDrag(dx,dy)` /
     `applyZoom(1.15)` / `flushCropLayout()` / `confirmCrop()` / `cancelCrop()` /
     `toggleCropView()` / `cropInfo()` —— 不用鼠标也能走一遍取景流程）、
   * `EmblemToolCore.ui.imageImport.applyImportedImage({data,width,height,name}, 'x.png')`
     （**走真路**导入一张图：算初值 → 重算 → 刷新 → **自动进取景模式**）、
   * `EmblemToolCore.ui.pipeline.pipelineStats()`（★ 性能哨兵：`prepareEmblem()` 与面板刷新各被调了几次。
     取景拖动期间它**必须不动**，点〔确定取景〕才 +1）、
   * `EmblemToolCore.emblem`（格式层：`saveKind` / `verifyChecksums` / `extractImage` …）、
   * `EmblemToolCore.card`（记忆卡层）。
   例如 `EmblemToolCore.emblem.saveKind(EmblemToolCore.ui.state.card.card.buf)`。
5. **取景"确定以后图不见了"**：0.6 已经修掉（见 §五 末"v0.6 修掉的两个 bug"）。
   如果你还在旧产物上遇到，先在 Console 里跑
   `EmblemToolCore.ui.state.prepared.report.compliance` —— 里面 `issues` 会说明为什么不合规。
6. **取景拖动还是卡**：先确认版本号是 `v0.26`（0.7 以前的产物在 1000×800 的照片上实测一次拖动要 **397 ms**）。
   然后可以在 Console 里量一下：
   `const t=performance.now(); EmblemToolCore.ui.cropView.applyDrag(50,0); EmblemToolCore.ui.cropView.flushCropLayout(); console.log(performance.now()-t)` ——
   正常应当是**零点几毫秒**；如果是几十上百毫秒，请连同 `pipelineStats()` 的输出一起发我。
7. **布局看着不对**：报之前先**拉一下窗口宽度**试试 —— 上区 `≤1100px` 会自动上下堆叠、
   `≤760px` 更窄；"当前图片"那一块是 128×128 的方画布（绝不会拉伸），
   所以窄窗口下留白变多是正常的。

## 七、打包器的 import/export 纪律

`build.mjs` **只支持这一种子集**，遇到不支持的写法会**报错并指出文件与行号**（不静默产出坏包）：

支持：具名导入（多行、`as` 别名、内联 `type`）、纯副作用导入、`import type`、
`export const|let|var`、`export function`、`export class`、`export { a, b as c }`、
`export type|interface|declare`，以及唯一的 re-export 形式（`export` + 星号 + `as`，
用于把核心层挂到 `window.EmblemToolCore` 供 F12 手查）。

不支持（一律抛错）：默认导入、`import * as ns`、`export default`、动态 `import()`、
`import.meta`、`export * from` / `export {a} from`、裸模块名、少写扩展名、循环依赖。

写 UI 时的四条纪律（都是踩出来的）：

* **注释里不要写落单的反引号**（同行内不配对）。打包器要先掩掉注释才能安全地找关键字，
  而注释里的反引号在 JS 词法里是模板字面量界符 —— 一个落单的就会把后面几百行吃掉。
* **注释里不要出现标签字面量**（`<link>` / `<script>` 的写法）。自检要按标签数扫全文，
  注释里的字面量会被数成真标签。
* **注释里不要写出被测试禁止出现的字面量**（例如顶栏那句旧的占位文案、旧版本号 `v0.x`）。
  注释会被打进产物，测试在产物里搜那几个字就会红 —— 这类断言看起来"莫名其妙失败"，
  原因往往就是自己写的注释。
* **"有没有调某个函数"这类断言要打在 `maskSource()` 之后的源码上**。否则"我们故意不调
  `recompute()`"这种解释性注释会被当成"真的调了" —— `ui.test.ts` 分节 (l9) 第一版就栽在这里。
