## 一、目标与交付形态

**一句话**：把 PC 上任意一张图变成 PS2《装甲核心》能用的徽章，直接写进记忆卡；也能反过来看/导出/搬运卡上的徽章。

| 项 | 决定 |
|---|---|
| 形态 | **单个 HTML 文件**，双击离线打开即用（`file://`） |
| 面向谁 | **别人 0 安装**：不装 Python、不装 Node、不装任何东西，只要浏览器 |
| 浏览器 | Chrome / Edge 为主（开发机 `Chrome 154` / `Edge 154`）；Firefox 尽力兼容 |
| 不做 | 不做在线服务、不做账号、不联网（**完全离线**）、不做动画预览 |

★ **版本号规则（用户 2026-10-04 定）**：从 **`v0.1`** 起数，**每次交付 +0.01**（粒度 0.01 ⇒
每一轮界面微调/修正都发一个小版本号）；
**只有用户明确说"可以发布了"才允许进 `1.x` 正式版**。界面顶栏显示它（不要再写"单文件离线版"之类）。
当前交付版本 **`0.47`**（界面显示 `v0.47`），界面开发标记 **`M4-UI-48`**。
唯一来源：`web/src/ui/logic/version.ts`（`APP_VERSION` / `UI_BUILD_TAG` / `APP_VERSION_LABEL`）——
构建脚本**从源码读**（不写死第二份），并硬校验 `^0\.\d+$`，不合规直接构建失败。
★ `version.ts` 现在**只有版本号 + 规则**（35 行）。历史既不写在这里、也不单独维护文档：
0.19 之前它文件头挤着 **140 行注释**的变更史，而打包器**不删注释** ⇒ 每个下载单文件产物的人
都白背一份；**现在统一由 git 记录**（想看某一版改了什么：`git log`）。

★ **已知限制（浏览器硬规定，不是我们的选择）** —— 2026-10-06 在 **Edge / Chrome 154 + `file://`** 上逐条实测：

```
✅ file:// 是安全上下文（isSecureContext=true）⇒ 三个 FSA 选择框（open/save/directory）**都在**；
   但**必须有用户手势**：没有手势调 showOpenFilePicker() 抛 SecurityError
   （原文："Must be handling a user gesture to show a file picker."）⇒ 启动时**不可能**自己弹选择框。
✅ 句柄能记住：FileSystemFileHandle 可以存进 IndexedDB 再取回来（8 MiB 写 26 ms / 读 11 ms，
   配额约 10 GiB，跨浏览器进程仍在）。
❌ 凭路径读本地文件：file:// 页面里用 fetch / XHR 读**同一个 file:// 地址**一律被拦
   （TypeError: Failed to fetch）⇒ 不存在"按 C:\…\Mcd001.ps2 直接读"这种写法。
❌ **选择框也不能指定路径**：startIn 只收"已知文件夹枚举"（documents / downloads / desktop …）
   或一个**目录句柄**；写 'C:\…\memcards' 这类字符串**没用**（→ 见 §三「选择框开在哪」）。
❌ OPFS（navigator.storage.getDirectory()）在 file:// 下抛 SecurityError
   （加 --allow-file-access-from-files 才行 —— 用户双击产物时不可能带这个开关）⇒ 当不了缓存。
⚠ file:// 页面**留不住授权**：官方文档对此**没有说法**（WICG #102 问的正是"本地 HTML 能不能留住句柄"），
   反面证据有两条 —— ① 2015 年 Chromium 一条 CL 明说 file:// 下没法记住权限偏好，因为
   "file:// URL 缺少清晰的来源概念"；② "每次访问时都允许"（Chrome 122 起默认开启，M121 还是关的）
   在源码里挂在 FILE_SYSTEM_ACCESS_EXTENDED_PERMISSION／**已安装的 PWA** 上。本机实测：Edge 配置里
   file_system_access_restore_permission 是空的 ⇒ **凡是要跨会话的东西一律别指望**。
⚠ **所有 file:// 页面共用一个来源**（实测 location.origin === 'file://'，不是 opaque）⇒ localStorage /
   IndexedDB 是**所有本地 HTML 共用**的（别往里放私密东西；"清除浏览数据"会把它们一起清掉）。
```

所以文件进出走"**选择文件 / 下载文件 / 记住句柄（仅本次会话）**"，具体保存流程见 §三。

## 三、文件访问与保存流程

**实测事实（2026-10-04，Chrome 154 双击 `file://` 打开 `probe.html`）**：

```
protocol=file:   isSecureContext=true
showOpenFilePicker / showSaveFilePicker / showDirectoryPicker  三个 API 全在
① <input type=file> 读记忆卡（8,650,752 字节，头 "Sony PS2 Memory "）  ✅
③ showSaveFilePicker() 拿到保存句柄                                   ✅ ★ 关键
```

⇒ **`file://` 这一档就能"打开原卡 → 改 → 直接覆盖保存"**，不需要"下载→手拷"那一套。
Chrome 把 `file://` 当安全上下文，所以 File System Access API 在这里可用（Firefox/Safari 没有这些 API，
对它们的降级方案见下）。

**主流程（Chromium / 双击打开）**

```
选择记忆卡（showOpenFilePicker，mode:'readwrite' → 拿到句柄）
      ↓ 读进内存（Uint8Array）→ 列出 8 个槽 → 编辑/加工
写入：① 先生成一份改好的卡在内存里并自检（逐字节 + 18 段校验）
      ② 用同一句柄 createWritable() **直接覆盖原卡**（⚠ 上游 C++ 工具会先写一份 `<存档>.backup`
         旁路文件；网页版**不做这一步**，备份靠用户自己 —— 见 §八 1）
      ③ 回读校验（重新 getFile() 读一遍比对）
```

**降级流程（Firefox / Safari / 没有这些 API）**：`<input type=file>` 读卡 → 处理后**下载**（文件名与原卡一致）
→ 提示"先完全退出 PCSX2，再拷回 `memcards\`"。
★ 降级入口是**自动**的（`openCardViaPicker()` 发现没有 `showOpenFilePicker`、或被拒绝时自己点隐藏文件框）。
顶栏**没有**〔拖入 / 只读选择〕按钮（`v0.10` 按用户要求删掉了，原话"没用"）；`#card-input` 这个隐藏文件框保留。
**拖入**仍然是兜底的一条路：把 `.ps2` 拖到顶栏「记忆卡」那一块上（Chrome 下拖放还能拿到写句柄）。
★ 顶栏那行"卡信息"**只有两段**：**锁状态**（`🔓 文件名` = 能直接覆盖保存；`🔒 文件名（只读 · 保存=下载）`）+ **卡文件大小**。
★ `v0.30`（用户）：锁状态里**不再写那个后缀**（"（可覆盖保存）"几个字嫌多余）⇒ `🔓` 这一档只剩文件名，
含义由这里的文档 + `README.md` 承担。⚠ 别把那几个字抄回注释：`ui.test.ts` 分节 (r) 的判据是"产物里一个都不许有"。
`v0.27` 起**不再列整卡徽章目录**（原来第三段是 `目录名(N 项 · LR)` 串一长行；用户："我认为这一段内容
没有显示价值的，删了吧" —— 那属于"说明性文字"，而 8 槽那一段已经写明"卡上还有其它作品…（切作品查看）"）。

★ **〔选择记忆卡〕的选择框开在哪**（`v0.30`，用户："点击选择记忆卡就自动到 `C:\Users\M\Documents\PCSX2\memcards` 路径下"）：

| 顺序 | 条件 | `startIn` | 效果 |
|---|---|---|---|
| ① | 自检面板里选过 PCSX2 目录、授权还在（句柄已在启动时/选目录后缓存好） | 那个目录下的 `memcards` **目录句柄**（`getDirectoryHandle('memcards')`） | 选择框**直接开在 memcards 里**（8 张卡一眼可见） |
| ② | 上面那条拿不到（没选过 / 授权掉了 / 里面没有 memcards） | `'documents'` | 开在**「文档」** `C:\Users\M\Documents` ⇒ 双击 `PCSX2` → 双击 `memcards` |
| ③ | 两个都炸（不是用户取消的那种错误） | —— | 退回只读兜底（`<input type=file>`），与 `v0.29` 一样 |

* ★ **为什么不能直接写那条路径**：`startIn` 只收**已知文件夹枚举**或**目录句柄**，页面上写
  `'C:\Users\M\Documents\PCSX2\memcards'` 是**无效**的（§一 那张实测表）。所以能做到的最准一档就是 ①，
  而 ① 的授权在 `file://` 下**只活一次会话**（浏览器不给跨会话）⇒ 大多数时候看到的是 ②。
* ★★ **句柄是"缓存"的，不是点击时现算**（`main.ts::memcardsHandle`；启动时 + 选完 PCSX2 目录后各刷新一次）：
  `showOpenFilePicker` 要的是**点击起 5 秒内的** transient activation，若在"点击 → 弹框"之间夹一个 `await`
  （开 IndexedDB / 查权限），一旦 IDB 被别的标签页卡住就会**手势过期** ⇒ 弹框被拒、**静默掉进只读兜底**
  （那是个很坏的退化）。`ui.test.ts` 分节 (r) 拿**掩码源码**钉住"那一段里不许出现异步等待"。
  没缓存时点击会**顺手刷一次**（`void refreshMemcardsHandle()`，但**不等**它）⇒ 第二次点就能开在 memcards。
* ⚠ 候选阶梯里**只有一处 `isAbort()` 判断**：用户按一次取消**不会再弹第二次框**（同一条闸门钉住）。
* 按钮的 `title` / `data-en-title` 写着这件事（鼠标停一下就能看到开在哪），免得用户以为"怎么老开在文档"。

★ **中/日/韩/英四语 + 顶栏最右的语言下拉**（`v0.28` 起中英；`v0.47` 加日/韩 —— 用户："ac 的受众主要就是中日欧美韩"，
所以**四种语言就是终点**）：

| 项 | 定案 |
|---|---|
| 位置 | 顶栏**最右**（`</header>` 前一个 `.topbar-block.lang-pick`，`margin-left: auto` 顶到最右；窄屏靠 `.topbar` 的 `flex-wrap` 折行 ⇒ 不需要额外断点） |
| 选项 | **中文**（默认）/ **English** / **日本語** / **한국어**，顺序即 `i18n.ts::LANGS`。⚠ 语言名**不翻译**（中文就叫"中文"）⇒ 它不算"漏翻"，见 `tools/i18n-audit.mjs` 的白名单 |
| 标签 | 写死四语 **`语言/Language/言語/언어`**（`v0.36` 双语起步，`v0.47` 按用户"写死的双语改成 4 语，行宽不是问题"扩成四语）—— 四种语言下都是这一句、**不参与翻译**。它是**唯一**一个不带 `data-*` 的静态标签（样式与判据见 ★ `v0.36` 那条） |
| 默认 | **中文**；首次打开按 `navigator.language`：`zh*`→中文、`en*`→English、`ja*`→日本語、`ko*`→한국어，**其它一律中文**（不瞎给英文） |
| 记住 | 用户**手动切**才写 `localStorage`（键 `ac-emblem-tool:lang`，就是 `i18n.ts::LANG_STORAGE_KEY`）；自动判定**不写** ⇒ "换个浏览器语言"仍会跟着走，手动切过之后永远听用户的 |
| `file://` | 能记住（Chrome/Firefox 的 `file://` 有 `localStorage`）；读写都包 try/catch ⇒ 失败只退化成"本次有效"，不报错、不影响启动 |
| `<html lang>` | 按语言写 `zh-CN` / `en` / `ja` / `ko`（`i18n.ts::HTML_LANG`）。⚠ 它不只是无障碍：CSS 里 `html:lang(ja) body` / `html:lang(ko) body` 的**字体栈**靠它（中文默认的 `Microsoft YaHei` 会把日文汉字画成中文字形）；只用系统自带字体（Yu Gothic UI / Meiryo、Malgun Gothic、Hiragino / Apple SD Gothic Neo），**不打包 webfont** |

**写法（★ 关键设计：不建"键 → 文案表"）** —— 键表必然漂移（中文改了忘改日文、键漏了、拼错了），
而且中文要在产物里存两遍。所以用**原文就地配对**：

* **静态 HTML**：中文就是 DOM 原文，其余语言写在属性里 ——
  `<button data-en="Crop" data-ja="トリミング" data-ko="자르기">取景</button>`
  （属性类同形：`data-<lang>-title` / `-placeholder` / `-aria-label`）。
  `i18n.ts::applyStaticI18n()` 第一次跑时把中文原文**快照**下来，切换时按语言写回
  ⇒ 四种语言在同一行，改一个忘改另一个会被 `ui.test.ts` 分节 (p) 抓住。
  ⚠ **唯一的例外**是语言下拉左边那个标签：它写死 `语言/Language/言語/언어`、不带任何 `data-*`（`v0.36` / `v0.47`，理由见上表「标签」行）。
* **动态字符串**：`t('中文原句', 'English sentence', '日本語', '한국어', vars)`（`vars` 填 `{name}` 占位）——
  中文留在它本来在的位置，可读、可 `grep`，而且"断言产物里有某句中文"那些既有闸门**一条都不用改**。
  ⚠ **四个字符串实参一个都不能少**：`ui.test.ts` 分节 (p) 扫**每个** `t()` / `setStatusPair()` / `refusedNote()`
  调用（打在掩码后的源码上、按第 1 层逗号切实参），实参少于 4 个就报错 —— 少给一个那种语言就显示 `undefined`。
* **表数据**（作品表 / 缩放核）：`{ label, en, ja, ko, note, noteEn, noteJa, noteKo }`，
  渲染时才 `t(...)`（这两张表在漏翻审计的白名单里，理由写在 `i18n-audit.mjs::ALLOW`）。
  ★ 作品名**保留英文原名**，只翻地区后缀（`Silent Line 日版` → 日 `Silent Line 日本版` / 韩 `Silent Line 일본판`）。
* **切语言要重画 JS 生成的那部分**：`main.ts::relayoutForLang()`（作品下拉 **＋ 它右边那句未验证警告 / 报错红字**、
  缩放核下拉 / 语言下拉自己 / PCSX2 面板 / 顶栏卡信息 / 8 槽 / 写卡提示 / 状态行 / 图片区小字 /
  **取景读数与取景那句状态行** / **顶部"文件名 · 尺寸"** / **还开着的弹窗**）。
  ★ `v0.39` 的教训：作品那一段的文字原来**不在名单里**（下拉被重画成新语言、紧挨着的警告还是旧语言 ——
  用户截图：下拉是"AC2 ⚠ 未验证"、右边却是"⚠ Unverified: no real emblem sample."）。
  修法是**让同一个块里的文字由同一个函数产出**（`renderGameBlock()`，切作品 / 开机 / 切语言三条路都走它），
  这样"重画名单"才漏不了。
  ★★ `v0.40` 的教训（更根本的一条）：**凡是把"渲染好的字符串"存进 state / 闭包的，切语言一律换不过来** ——
  状态行（`state.status`）、剪贴板那张图的名字（`state.source.name`）、弹窗正文、提示条，全是这个毛病。
  现在的规则是：**state 里只存语言无关的东西（数据 / 标记 / 渲染函数），翻译一律在渲染那一刻做**
  （`setStatus(text, redo)` / `setStatusPair()` / `showModal(() => ({…}))` / `src.clipboard`）。
  ⚠ 提示条是唯一的例外（30+ 个调用点不值得全改）：切语言时**直接收掉**（`dismissToasts()`），
  宁可消失也不留旧语言的话。
  ⚠ **有意不重画**：写入日志（历史记录）、`main.ts` 里那些一次性 toast 文案。
  **有意不重画**：写入日志（那是历史记录）、已弹过的 toast、弹窗正文（`.modal-host` 是整页遮罩
  ⇒ 它开着的时候点不到语言下拉，不存在"弹窗开着切语言"）。

## 五、图片管线（任意尺寸 / 任意格式 → 工具可用格式）

**输入**：PNG / JPEG / WebP / GIF（首帧）/ BMP / ICO / AVIF / SVG；**剪贴板粘贴（Ctrl+V）**；拖拽；批量。

七步，每步都可调 + 实时预览：

| 步 | 内容 | 已定默认值 |
|---|---|---|
| ① 解码 | `createImageBitmap(file, {imageOrientation:'from-image'})`（按 EXIF 摆正） | — |
| ② 取景 | 适应 / 铺满 / 拉伸 / **手动**（核心四档）<br>★ **界面只有「手动」一档**（`v0.13`） | ★ **默认直接进"手动"**（拖拽平移 + 滚轮缩放 + **滑条/输入框精确调白框边长**（`v0.38`），确认后生效）；**手动的初始值 = "填满白框"**（窗口边长 = 源图短边、居中，`v0.9` 用户定）<br>★ 参数行那个四档下拉**已删**（用户："这四个下拉选项有什么意义呢，我感觉只需要一个就行了"）：`core/image.ts::fitToTarget()` 里**只有 `manual` 会读界面给的 `scale/offsetX/offsetY`**，另外三档会自己重算一套 ⇒ 那个下拉实际是"偷偷丢掉你的取景"的开关；而手动能覆盖前两档（滚轮往里 = 铺满；往外滚到底 = 适应留边），只有「拉伸」做不到（徽章不该被拉伸）。`fitMode` 恒为 `'manual'`，导入图片时 `fillManualToTarget()` 会再钉一次。**核心四档一个都没动**（`image.test.ts` 仍在跑 contain/cover/stretch 的几何判据） |

| ⑥ 索引语义 | **索引 0 = 透明/背景**，1..255 = 实色 | 非 LR 需**可逆乱序置换**；LR 不需要 |
| ⑦ 合规校验 | 尺寸 128×128 / 不透明色数 ≤255 / 半透明 0 个 | **不满足就拒绝写入并说明原因**（宁可不写，不写坏卡） |

★ **所见即所得**：界面上的"游戏预览"必须按**索引 0** 渲染（不是 alpha）—— 这是实机验证过的游戏口径，

★ **参数化尺寸/色数**：`targetSize` / `maxColors` 不写死，PS1（**64×64、15 色+透明**）将来只换参数。

## 六、编辑器 → **明确不做**（`v0.22` 定案，原 M4b 取消）

用户 2026-10-06：「我突然觉得我们是不是没有必要做工具这一栏，毕竟其他优秀的图像处理工具有很多」
⇒ 讨论后选「整块删掉」。**理由（写在这里，免得以后又想起来做）**：

1. 这个工具真正难、真正值钱的是**格式与写卡** —— 18 段校验、末段校验字节的**真实位置**、ECC、
   FAT 簇链、目录项、`icon.sys`、LR / 非 LR 两套布局。那部分**已经做完**（8/8 判据全绿）。
2. "能画图"不是它的核心价值，而内置编辑器会**明显不如** Aseprite / Piskel / Photoshop / 画图
   （笔压、图层组、滤镜、成熟撤销），却要吃掉"判据最难写、最容易埋 bug"的一整块（撤销栈、选区、
   填充边界、图层合成），**且不增加任何可靠性价值**。
3. **闭环已经存在、而且是无损的**：〔导出 PNG〕导出的就是**游戏口径**（索引 0 = 透明）⇒
   外部工具随便改 ⇒ 拖回工具 ⇒ 覆写。

### 替代流程（外部编辑器承担"画"）

```
卡上 / 工具里的图 ──〔导出 PNG〕──▶ 外部编辑器（128×128，保留 alpha）──▶ 拖回工具 ──▶ 取景 ──▶ 写卡
```

★ **为什么这条闭环是无损的**（两半都有判据，不是"应该没问题"）：

* **导入侧**：128×128 的图，取景默认值（"填满白框"）恰好是**恒等映射**（倍率 1 / 偏移 0）
  ⇒ `core/image.ts::fitToTarget()` 走恒等短路（`v0.19` 的 D20 保证"只有真恒等才短路"）。
  判据：`ui.test.ts` 分节 (i)「128×128 ⇒ 1,0,0」。
* **减色侧**：≤255 色的图 ⇒ `quantizeOpaque()` 返回 `exact: true`，一个像素都不换色。
* **合起来**：`image.test.ts` 的「★ 0.22 闭环」一节 —— 导出 → 重新导入 ⇒ **逐像素 `diff = 0`**、
  透明像素数不变（"洞"还在）、实色数不变、索引 0 仍只落在透明像素上、再转一圈不漂移。
* PNG 编解码本身无损（无损压缩、8 bit/通道）；浏览器里那一段由无头探针真走一遍
  （`canvas.toBlob('image/png')` → `createImageBitmap` → 真路导入 ⇒ `diff = 0 / 16384`、
  `transparent 6736 → 6736`、`compliance = true`）。

⚠ **代价（如实记）**："0 安装"这条承诺在"凭空画一个徽章"这件事上缩水了 —— 想从零画的人需要
先有个画图软件（画图 / Piskel 网页版都行）。**写卡这条链仍然零安装。**

## 八、可靠性规矩（每一条都是踩出来的，写进代码而不是写进说明书）

1. 写卡前**强制用户自己备份**（打开页面时弹一次确认框，`main.ts::boot()`）+ 提示**先退出 PCSX2**。
   ★ 网页版**不写** `.backup` 旁路文件（那是**上游 C++ 工具** v1.0.1 起的行为，见
   `docs/01-项目理解/05-源码导读.md` 的 `ModifySave()`）—— 别以为工具替你备份了。我们这边能保证的是：
   原卡**全程只读**（只在内存副本上改），源字节在内存里留一份，落盘前必弹确认框写明"要覆盖哪个文件"。
   ★ `v0.25`：**落盘前先比一次文件时间戳**（选卡时记下 mtime/size，每次成功落盘后更新）。
     不一样 ⇒ **拒绝写入/删除**并说清"哪个文件、什么时候变的、接下来三步"（`logic/staleness.ts`）。
     理由：Chrome 的句柄会因"文件被别的进程改过"而过期（`InvalidStateError`），而 **PCSX2 开着时
     随时可能把手里的卡写回文件** —— 与其写到一半炸掉，不如动手前就拦住。
   ★ `v0.25`：〔删除槽〕也走**同一条落盘路径**（`persistCardChange()`）：确认框 → 内存副本上删 → 覆盖 → 回读文件比对。

7. ★ `v0.43`：**一条事实只在一个主位讲全文，其它渠道只留指针或一句话** —— 同一条消息在屏上出现 4~5 遍
   会让人找不到重点。落到写入路径上就是**两级拒绝**（`cardOps.ts::writeSlot()`）：
   · **预检拒绝**（`reject()`：没开卡 / 没模型 / 图像没准备好 / 作品常量没依据 / 目录不存在 / 目标不属于本作品）

   · **动作之后的失败**（`fail()`：内存写入失败 / 回读自检不过）⇒ 日志里必须有逐条证据，
