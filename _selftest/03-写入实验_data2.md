### ★★ 实机结果（用户 2026-10-04 实测截图确认）

**写入链路通过**：游戏把 `Mcd001_embdata2.ps2`（挂在 slot 2）读出来了，
第 3 个徽章格显示**反色的恶魔脸** —— 说明"新建文件 + 分配簇 + FAT + ECC + 目录项 + 项数"
这一整套都对。

**顺带把"半透明"那个悬案定案了**：反色后 `palette[0]` 是 **`FF FF FF 40`**
（RGB 全白、alpha 保留 `0x40`），预期是"50% 白底"。实机观测：

| 假设 | 预期 | 实测 |
|---|---|---|
| alpha 当真（0x40 = 50%） | 成片中灰 | ❌ 找不到成片中灰（100–190 只有散点） |
| 忽略 alpha、按 RGB 画 | 纯白 | ❌ 找不到成片纯白（>250 的众数是奶白 `(225,228,203)`，那是反色的恶魔身体） |
| **索引 0 = 背景/透明** | **黑** | ✅ **背景仍是黑的** |

⇒ **游戏不把索引 0 的 RGB/alpha 当颜色画；索引 0 就是背景色。**
因此 `extract_image` 新增了 **`--alpha index0`** 档（索引 0 透明、其余不透明），
它才是与实机一致的提取方式；`acet`/`gs` 两档在 `data2` 上都与实机不符。
详见 `../docs/01-项目理解/02-存档格式规范.md` §五 与
`../docs/01-项目理解/07-限制与已知问题.md` 问题 20。

## 二、写了什么

把 `data0`（恶魔脸）的**调色板 RGB 逐项取反、alpha 原样保留**，作为新槽 `data2`：

```
palette[0]:  00 00 00 40   →   ff ff ff 40
             ↑ 半透明黑        ↑ 半透明白（alpha 0x40 保持不变）
反了 768 个通道（256 项 × 3 通道），重算 18 段校验 → 18/18 通过
```

⇒ 游戏里这一格应该显示**反色的恶魔脸 + 半透明白底**。
★ 这个设计是故意的：**如果游戏里那层白底是半透明的，就直接证实了 `0x40` = 50%**（限制问题 20）。

## 三、写入清单（实际做了什么）

| # | 动作 | 细节 |
|---|---|---|
| 1 | 复制卡 | `Mcd001.ps2` → `Mcd001_embdata2.ps2`（源卡只读） |
| 2 | 构造反色徽章块 | 17,440 B，调色板 RGB 取反、alpha 不动、重算 18 段校验 |
| 3 | 分配簇 | **18 个**空闲簇（17,440 B ÷ 1024），rel **1390–1407** |
| 4 | 写数据 + ECC | 18 簇 × 2 页 = 36 页，每页重算 ECC |
| 5 | 写 FAT 链 | `0x80000000 \| next`，末簇 `0x80000000 \| 0x7FFFFFFF` |
| 6 | 加目录项 | **克隆 `data0` 的 dirent**（改名为 `data2`、改首簇、长度不变），写进 EMB 目录**第 7 号空槽** |
| 7 | 改项数 | **根目录**里 `BISLPS-25462EMB` 条目的 `length`：**7 → 8** |
| 8 | 回读校验 | 见下 |

### 目标目录的关键结构（写之前先摸清的）

```
根目录条目 [BISLPS-25462EMB]  mode=0x8427  length=7  cluster(rel)=1320
  目录簇链 [1320, 1321, 1368, 1371] = 4 簇 = 8 个 512 B 槽位
  槽 0 '.', 1 '..', 2 static.ico, 3 data0, 4 icon.sys, 5 BISLPS-25462EMB, 6 data1,
  槽 7 = 0xFFFFFFFF（空）   ← 正好够放一个新项
```

★ 两个**事先不知道、靠实测才确认**的点：

1. **项数不在 `.` 项里，在根目录条目里。**
   子目录的 `.` 项 `length` 恒为 **0**（EMB 与 GAME 都是），
   而**根目录里那个目录条目的 `length`** 才等于项数（EMB=7、GAME=9）。
   ⇒ 只改 `.` 项是**无效**的。（`dir_count()` 对这种目录会返回 0，别拿它当项数。）
2. **同名的 32 字节"存档头文件"里没有项数**（EMB 与 GAME 的这份内容完全相同，
   都是 `00 00 00 00 01 00 00 00` + 24 个 0）⇒ 不需要动它。

## 五、怎么在 PCSX2 里测（✅ 已按此测过，见 §一）

1. **先关 PCSX2**（它开着的时候不会重新读卡）；
2. 把 Memory Card **slot 1 或 2** 指到 `Mcd001_embdata2.ps2`；
3. 启动 ACLR（日版）→ 进**徽章**/记忆卡画面；
4. 该看到的：**第 3 个徽章格**变成**反色的恶魔脸**。 ← ✅ 已确认

## 六、这次实验**没有**证明的

* 只测了**"在已有目录里加一个文件"**，没测：新建目录、扩目录（簇不够时）、删文件、改文件长度；
* 没测**游戏会不会真的接受**这个新卡 —— 那要靠你实机跑（按工作区规矩，PCSX2 你自己开关）；
* 反转的只是调色板，**没有重排像素索引**，所以颜色数、索引分布与 `data0` 完全一样；
* `data2` 的 dirent 是**克隆 `data0`** 的，所以它的时间戳与 `data0` 相同（不影响功能）。
